# MC Translator · 模組包繁體中文化

把 Minecraft 模組包（模組、任務、Patchouli 等書本、KubeJS、設定檔）翻成台灣用語的繁體中文，並在套用前自動備份原檔。

## 下載與使用

**[直接下載最新版 MCTranslator.exe](https://github.com/siang86121900/mc-zh-tw-translator/releases/latest/download/MCTranslator.exe)**，雙擊即可，不需要安裝 Python。瀏覽器若顯示「這個檔案不常被下載」請按「保留」；Windows 若跳出「Windows 已保護您的電腦」，按「其他資訊」→「仍要執行」。想看更新說明可到 [最新版下載頁](https://github.com/siang86121900/mc-zh-tw-translator/releases/latest)。

1. **關閉遊戲**，從下拉清單選擇模組包（會自動列出 CurseForge、Modrinth、Prism、MultiMC、ATLauncher 的模組包和你用過的資料夾）。找不到時可直接貼上路徑，或按「選擇資料夾」。選到模組包裡的 `mods` 之類的資料夾也沒關係，程式會改用模組包本身；選到放了好幾個模組包的外層資料夾，會請你選其中一個。
2. （選用）勾選：
   - 「用 AI 補翻缺漏，並核對有疑點的譯文」：需要先在「AI 帳號與模型」連接 ChatGPT
   - 「套用後把遊戲語言設為繁體中文」：修改 `options.txt`，一樣會備份、可還原；不勾就自己在遊戲裡切換
3. 按 **一鍵完整翻譯並套用**，等它跑完。
4. 重新啟動遊戲，語言選「繁體中文（台灣）」。

遊戲沒關也沒關係：譯文和報告會先保存，關掉遊戲後按「重試套用」即可，不用重新翻譯。啟動器可以開著：寫入時若檔案剛好被啟動器或防毒軟體打開，程式會稍等並自動再試。跑完時會跳出 Windows 通知，工作列圖示也會顯示進度。

## 翻譯邏輯

按下「一鍵完整翻譯並套用」後，程式依序做這些事。參考來源能翻的會先寫入遊戲（通常幾分鐘），這時遊戲已經是中文；AI 補翻比較慢，做完再寫入第二次。

### 1. 確認參考庫是最新版

- **必須是最新：** [ModsTranslationPack](https://github.com/TeamKugimiya/ModsTranslationPack)（繁中）與同版本 [CFPA](https://github.com/CFPAOrg/Minecraft-Mod-Language-Package)（簡中）。確認不到就停止，不會拿舊資料冒充。
- **怎麼確認：** 用沒有次數限制的方式向 GitHub 確認，網路不穩會自動重試最多 3 次；GitHub 的查詢服務（同一個網路每小時 60 次）只當備援。
- **Minecraft 版本：** 先讀啟動器的紀錄；啟動器沒有記錄時，從已安裝模組的需求推測，並在報告註明。
- **補充來源：** [ParaTranslationPack](https://github.com/TeamKugimiya/ParaTranslationPack)、CFPA 1.20／1.19／1.18、Minecraft 官方繁中。暫時取不到時只略過並記在報告。
- 使用的版本、下載時間與雜湊都會記在報告裡。

### 2. 掃描整個模組包

本機開發中的 v0.32.0 另做文字涵蓋檢查：核對每個文字位置，不因同一檔案已有幾筆條目就當成全部掃到。短名稱、按鈕和內嵌壓縮檔也會檢查；讀取失敗或超過範圍會保留原因。新發現的候選只用來揭露尚未支援的內容，必須另行確認遊戲用途才能翻譯。完成提示直接列出未支援範圍、未讀完的檢查與具體疑點，不要求逐筆人工確認。完成率只代表已辨識文字的檔案狀態，尚非遊戲畫面實測，也不能保證未知格式或存檔中的文字都已翻好。此版尚未公開發布。

讀取 `mods`（含內嵌在模組裡的函式庫）、資源包、資料包、KubeJS、CraftTweaker 腳本（`scripts` 資料夾）、設定檔、任務、Patchouli 等書本，以及 TACZ 槍械包（`tacz`）和車萬女僕的自訂模型包（`tlm_custom_pack`），找出所有玩家看得到的文字。沒變動的模組會沿用上次的掃描結果。有含中文或疑似顯示欄位、卻沒有產生任何翻譯列的檔案，以及整合包裡程式還不會讀的資料夾中含中文或語系檔的檔案，會先自動處理能安全處理的部分：引號內的簡體字原地轉成台灣繁體、缺少繁中的語系檔資料夾補上繁中語系檔。因為還沒確認遊戲會讀這些檔案，所以不算進中文化完成率，報告會用灰字說明，也可以還原。處理不了的檔案才會在報告上方用紅字列為「格式尚未支援」，不會默默當作已完成。

同一段文字並列多種語言的設定（例如 Ponderer 動畫教學的 `config/ponderer/scripts`，每段同時寫著英文和簡中）會在旁邊加上繁中；整合包作者的英文有時沒寫完，這時以完整的簡中轉成台灣用語。只有確認過模組會讀繁中的格式才會寫入，其他的列在報告並註明原因。

Whispering Quests 任務模組的任務（例如元素覺醒整合包，任務放在整合包作者自製模組裡的 `data/<模組>/whisperingquests/`）：這個模組直接顯示任務檔裡寫的文字，不查語系檔，所以翻譯資源包蓋不到。程式把任務標題、說明、目標、獎勵名稱與章節名稱轉成台灣用語（英文的交給 AI），連同任務檔其餘內容複製一份放進程式產生的資料包 `config\openloader\data\zz-MCTranslator-zh_tw.zip`，由 OpenLoader 放在所有模組上面讓每個世界讀取（包含已經開過的世界）；模組檔本身不修改。任務進度只記在存檔裡、不含文字，換成繁中不影響進度。模組更新時會用新的任務檔重新製作，不會用舊的複本蓋掉新內容。Minecraft 1.21 的新版 OpenLoader 改讀 `config\openloader\packs`，程式會自動放到那裡。整合包沒有 OpenLoader 時不寫入，報告會寫明原因。

模組程式要找、卻連英文都沒有的名稱：有些模組把名稱寫在和它註冊時不同的代號底下（例如註冊為 cobblemon-additions、名稱寫成 block.bca.pokemon_spawner），或直接拿整句英文當代碼去查（例如「Spawner: %1$s」），遊戲連英文版都只能顯示代碼。程式會在翻譯資源包補上遊戲實際要找的名稱，模組檔不修改；原文用了遊戲看不懂的數值格式（例如 %2$i）時，譯文改用看得懂的 %2$s 讓數值正常顯示，並列在「建議確認」。

以下文字從 v0.30.0 起也會翻譯（2026-10-03 對 7 個整合包逐檔盤點時發現先前整類漏掉）：
- 寶箱撿到的物品名稱與說明、進度標題：資料檔寫了語系鍵，但整個整合包沒有任何語系檔定義那個鍵，遊戲只好顯示英文（例如 Incendium 的武器、Pixelmon 的研究任務）。程式把這些鍵補進翻譯資源包。
- 主選單、暫停畫面的英文按鈕與說明文字（FancyMenu），翻好後寫回版面檔；圖片、顏色碼與 `{"placeholder":…}` 這類代碼保持原樣。
- 光影的設定選單：在光影包的語系資料夾加上繁中語系檔（有簡中的轉成台灣用語，只有英文的交給 AI）。
- 模組自己的圖鑑與百科：冰與火的生物圖鑑、Saint's Dragons 的龍圖鑑、Chrono Dawn 的 Chronicle、Tensura 的遊戲內百科（原本顯示簡體）。
- 被模組當成語系鍵顯示的 NPC 台詞與名稱：Pixelmon 的訓練家台詞、寶可夢中心等 Cobblemon 對話、Apotheosis 小頭目的名字。
- 資料包裡的任務：Slime Throne 的每日任務名稱、Monster Expansion 的委託與怪物圖鑑（和 Whispering Quests 一樣放進翻譯資料包）。
- 模組用自己的點陣字型畫、字型裡沒有中文的文字（例如 Beyond Adventures 的任務名稱與召喚說明）會保留英文，報告用灰字寫出原因。模組 `assets` 裡有文字、但程式還不認得格式的資料夾，報告會用紅字列為「格式尚未支援」。

資料包裡照字面顯示的文字：結構裡的 NPC 名稱與商店分類（例如寶可夢商店店員的「Cobble Balls」）、告示牌、放在建築裡的書，指令函式送出的系統訊息與給玩家的書，戰利品表與進度裡寫死的名稱，村民交易地圖的名稱（VillagerConfig 交易檔），寶藏袋的名稱，REI 物品清單自訂分組的名稱，以及 RCT 訓練家名稱。建築裡用舊格式存的書（例如 Pixelmon 海盜船上的日記）也會讀。這些不查語系檔，所以直接在原檔裡只改文字（整合包自帶的資料包，以及 CurseForge 不會換回的模組），改之前會備份、可以還原；CurseForge 會換回的模組列為「無法寫入」。結構檔只影響之後新生成的建築，已經出現在世界裡的 NPC 與告示牌存在存檔裡，程式不修改存檔，所以會維持原文。沒有讀取器、但顯示欄位有中文或英文句子的資料格式，會在報告用紅字列為「格式尚未支援」。

模組放在 data\<模組>\lang\ 的語系檔（例如 Lenient Death 透過內嵌的 Server Translations API 讀取）：遊戲顯示時會先查資源包裡的語系檔，所以譯文寫進翻譯資源包的 assets\<模組>\lang\zh_tw.json，模組檔不修改。

整合包裝了 Default Options 模組時，它會在第一次開遊戲把資源包清單換成整合包作者預設的那份。套用時程式會把翻譯資源包也加進那份預設清單（config\defaultoptions-common.toml）的最後面，讓它第一次開遊戲就啟用；修改前同樣會備份，可以還原。

生態域、結構和維度的名稱：很多模組在資料裡定義了它們，卻沒有在語系檔寫名稱，遊戲和自然指南針、探險家指南針就只能顯示代碼（例如 biome.jellyfishing.ghostly_graveyard）或把代碼變成英文（Abandoned Mine）。程式會找出這些缺少的名稱，照一般來源順序翻譯（找不到時交給 AI），放進翻譯資源包。原版自己的結構與分組（村莊、掠奪者前哨站，以及模組加在 minecraft 底下的結構）也一樣，寫進顯示它們的指南針模組的語系檔；有官方繁中名稱的（地圖與進度裡的叫法，例如針葉林村莊、綠林府邸、海底遺跡）直接用官方名稱。

結構名稱也要和地圖一致：名稱裡的生態域用小地圖顯示的官方名稱（例如「熱帶草原村莊」改成「莽原村莊」）；名稱留有英文（Alpine村莊）、或生態域叫法和地圖不同的，列在「建議確認」，也會交給 AI 核對。探險家指南針在 Xaero 地圖加的路標用的是同一個名稱；已經存在的舊路標名稱不會自動改。

整合包用 Paxi 載入的翻譯包（例如作者附的「探險者指南針結構漢化」）也會拿來當參考，只取中文名稱、去掉前面的模組名與後面的英文，英文對不上的不用；這些檔案本身不會被修改。同一個模組裡不同地方被翻成同一個名字、或模組繁中和簡中意思差很多的，會改用模組簡中或交給 AI 核對。設定檔裡寫的檔名不會被轉成繁體。

模組檔裡其他程式還不會讀、卻含中文顯示文字的資料檔（`data/` 裡 title、description 等欄位），會依資料夾在報告上方用紅字列為「格式尚未支援」，避免整類文字被漏掉。

FTB 任務書的文字（`config/ftbquests/quests/lang/` 裡的 `.snbt`）會逐行翻譯：整合包附的簡中任務檔會先轉成台灣用語，對不上的行再交給 AI，最後寫出繁中任務檔 `zh_tw.snbt`。英文任務檔不會被修改，圖片與換頁指令原樣保留。

任務文字直接寫在任務章節檔裡的整合包（FTB Quests 1.20.1，例如 The Foll），以及設定檔（`config`、`defaultconfigs`，含 `.yaml` 與舊式 `.cfg`）、KubeJS 腳本、CraftTweaker 腳本（`.zs`，例如物品提示）、槍械包顯示文字、FancyMenu 主畫面與暫停畫面的按鈕文字，以及 KubeJS 的視窗標題裡直接寫的中文：簡體字會在原檔轉成台灣用語，只改那段文字，其餘內容與排版不動，一樣先備份、可還原。二進位 NBT 設定的 `.data` 與 `.cache` 也支援，例如 SDMShop 的商店本體和畫面快取會一起處理；價格、數量、物品 ID 與其他 NBT 標籤保持原樣。設定的名稱（鍵名）、註解行、其他語言專用的檔案（例如 `lang/zh_cn.json`）不會改；整合包留著、遊戲不讀的 `quests-backup` 也不改、不計數。

設定說明與寫在模組程式裡的句子也會翻譯：目前支援能確認全部用途的 Forge／NeoForge 設定說明，以及直接傳給 Minecraft 顯示文字呼叫的常數，例如 AppleSkin 的「按住 SHIFT 顯示食物數值」說明。選用 AI 並同意後會補翻，沿用相同的額度保護、檢查、備份與還原流程；傳送範圍包含這些句子、文字位置與模組內相對路徑。重跑會認出已套用文字，保留 AI 來源。

這類文字通常只能寫回原模組。CurseForge 在啟動遊戲時會把它自己裝的模組檔換回原版，所以這些模組的這類文字不寫入、也不花 AI 額度，報告會寫明原因。你自己放進 mods 資料夾的模組（不是從 CurseForge 裝的）CurseForge 換不回去，會和其他啟動器一樣寫回原模組；模組程式裡寫死的簡體字也會轉成台灣用語：就算無法確認那句在哪裡顯示，只要它是單純的文字、模組沒有拿它去比對，就只轉字形（例如 Age of Mythology 的「巫法师」改成「巫法師」），意思不變。需要時可從備份還原。

有些模組會在遊戲啟動時修改其他模組的程式（Mixin），而且可能要找到一句指定的原文才能改；那句被翻譯後，遊戲會無法啟動。所以只要有任何模組會修改那段程式，裡面的文字就一律不改，報告會寫明原因。模組作者用來產生語系檔的工具程式裡的文字遊戲不會用到（遊戲讀的是模組附的語系檔，那份另外翻譯），列在「無需翻譯」。

例外是遊戲內設定畫面（模組清單的「設定」）顯示的設定說明：NeoForge 內建的設定畫面和 Configured 會先到語系檔找「設定的語系鍵.tooltip」，找不到才顯示程式裡的英文。所以在 CurseForge 整合包裡，能確認語系鍵的設定說明會翻譯並放進翻譯資源包，模組檔不修改。能確認的情況有兩種：模組替設定取了語系鍵（Forge、NeoForge 都適用，NeoForge 內建畫面與 Configured 都會讀），或模組使用 NeoForge 內建設定畫面（語系鍵是「模組 ID.configuration.設定名稱」）。模組沒取語系鍵、又不是用 NeoForge 內建畫面的（例如只靠 Configured 或 ForgeConfigScreens 顯示），畫面只會顯示程式裡的英文，仍列在「無法寫入（遊戲中是英文）」。這個做法只改遊戲內設定畫面，config 資料夾裡設定檔的註解仍是英文。一段說明分成好幾行時，要每一行都翻好才一起寫入。同一句說明在模組程式裡出現兩次（同一個語系鍵、同一句英文）時，會統一成最可信的一種譯法再寫入，你確認過的說法優先；原文不同的才會列出原因、不互相覆蓋。模組語系檔本來就有這句說明的，交由一般語系流程翻譯，也不會重複算進「還缺中文」。報告的搜尋也能搜尋疑點文字。格式 3 可分享有用途證明的 class 字串常數修改，不散布程式檔；對方須通過本機用途、Mixin、Java 與版本檢查。程式判斷用字串、公開常數、用途不明、註解標註或動態組句仍列為待查，不會只憑一句英文就直接替換。模組啟動後是否把說明更新到既有設定檔，取決於模組本身。

### 3. 先排除「遊戲不會顯示」的文字

- **沒安裝的模組：** 模組包附帶的整份翻譯包（例如放在 OpenLoader 的 CFPA）常含上千個沒安裝的模組，這些直接略過。別的模組為它準備的相容材質或配方，不算它有安裝；要有這個模組本身、它的語系檔或世界生成資料才算。
- **指向未安裝模組的名稱：** 例如 Traveler's Titles 裡其他模組的生態域名稱，也一併略過。

### 4. 每一句依序找中文，找到就停

原則是**最準確、最道地的台灣用詞**：
- 你親自確認的最優先。
- 人工寫的繁中優先於「簡中轉繁」，因為 OpenCC 轉不乾淨「設定／設置」「篩選器／篩檢程式」這類用語差異。
- 參考庫的繁中必須「英文和目前模組版本相同」才排在前面，避免用到舊版譯文。

| 順序 | 來源 | 說明 |
|---|---|---|
| 1 | 翻譯記憶 | 你在報告裡「確認這筆」校對過的譯文，綁定模組、語系鍵與原文 |
| 2 | 自訂譯名 | 你在「譯名與用詞」頁固定的譯名（整句相同才套用） |
| 3 | ModsTranslationPack | 台灣社群人工繁中；英文須確認與目前版本相同 |
| 4 | ParaTranslationPack | 台灣社群人工繁中；英文須確認與目前版本相同 |
| 5 | 模組包裡的繁中資源包 | 整合包作者安裝的 zh_tw 資源包 |
| 6 | 模組原本附的繁中 | 含簡體字的不採用；殘留的大陸用語（激活、添加、代碼、設置等）改成台灣用語並保留修正紀錄 |
| 7 | Mojang 官方繁中 | 原版物品、方塊、生物等官方譯名；整句比對只用在名稱，避免「Red」這類一般詞蓋掉模組自己的譯名 |
| 8 | 模組包裡的簡中 | KubeJS、OpenLoader、資源包的 zh_cn，轉成台灣用語 |
| 9 | 同一個模組附的簡中 | 轉成台灣用語 |
| 10 | CFPA（同版本） | 轉成台灣用語 |
| 11 | 版本待確認的參考庫繁中 | 英文和目前版本不同，或沒有英文可以比對，標示待核對 |
| 12 | 跨版本 CFPA | 1.20／1.19／1.18，標示「跨版本參考」並列為待核對 |
| 13 | 內建術語表 | 常用 Minecraft 名詞；官方有譯名的一律用官方的 |
| 14 | 含簡體字的既有繁中 | 轉成台灣繁體，標示待核對 |
| 15 | AI 補翻（選用） | 只補前面都找不到的；句子裡提到的物品會照用這包整合包已決定的譯名與你固定的譯名。同一個模組的同一句以前翻過就直接沿用，不再消耗額度 |

參考庫是資源包，在遊戲裡本來就會蓋過模組自帶的繁中，所以排在它之前。以 Tensura 為例，這個順序讓約 1 萬筆原本「簡中轉繁」或模組自帶的譯文，改用台灣翻譯組的人工繁中。

**簡中轉繁的寫法**
- **字形跟官方繁中一樣：** 寫「工作台」「基岩」「床」，不寫「工作臺」「基巖」「牀」。模組原本的繁中用了台、岩、床、群、峰，也不會被當成簡體。
- **修正常見的選錯字：** 一個簡體字可能對應好幾個繁體字，轉換工具遇到不認識的詞會選錯，例如松木變「鬆木」、最多只能變「最多隻能」、綁定變「繫結」、鐘石變「鍾石」；這些會自動改回來，模組自帶的繁中裡有同樣的錯字也會改正（「鍾愛」「情有獨鍾」不會被改）。
- **判斷是不是簡體字更準：** 「吃」「背包」「游標」「了解」「秘密」是台灣正常的寫法，不再被當成簡體字而降低模組自帶繁中的優先順序。
- **不改在台灣也正確的詞：** 例如「支持者」「質量」（重量）、「控制代碼」「錯誤代碼」、「數據機」「大數據」，以及「增加載入」這種剛好前後相連的字。
- **Minecraft 名稱用台灣官方譯名：** 簡中的「下界」「末影」「末地」「生物群系」「惡魂」「潛影」「刷怪蛋」等，依 Mojang 官方台灣繁中改成「地獄」「終界」「生態域」「地獄幽靈」「界伏」「生怪蛋」，「下界合金」改成「獄髓」。只換 Minecraft 專有的詞；「監守者」這種一般詞只在整句就是這個名稱時才換，模組自己的「地牢監守者」不會被改。舊版已寫入的這類用語會在下次執行時修正一次，並保留修正紀錄。
- **參考庫也一樣：** 台灣社群參考庫偶爾留著大陸用語（例如 Cloth Config 的「設置」），同樣改成台灣用語並保留修正紀錄，不會因為參考庫排序較前就蓋掉模組自帶的正確繁中。
- **數字不同只列出：** 模組自帶的繁中如果數字和英文不同（例如英文 30 秒、中文 15 秒），維持原文不改，但會列在「建議確認」的「數值和原文不同」。

**數值檢查**
- 譯文的數字和英文原文不同（例如原文「獲得 20 經驗」、譯文「獲得 10 點」），通常是中文來自模組的舊版本。
- 簡中轉繁、版本不同的來源遇到這種情況，會先改用數字正確的來源；都沒有才採用，並列入「建議確認」，寫出原文和譯文的數字。
- 中文數字（九十九、雙倍）和單位（1 萬＝10,000）不算不同。你確認過的譯文不檢查；模組為這個版本寫的繁中不會被換掉，只會列出。

**同一句出現在好幾個檔案時**
- 整合包常把同一個模組的同一句放在三個地方：模組本身、附帶的語言包（例如 OpenLoader 裡的 CFPA）、KubeJS。遊戲只顯示最上層的那一個。
- **只有中文、沒有英文的檔案：** 用已安裝模組的英文來比對和檢查；報告的「原文」欄顯示這句英文，滑鼠移上去可以看到檔案裡原本的中文。完全找不到英文時，參考庫的譯文不當成已確認。
- **每個檔案用同一個譯文：** 取來源最可靠的那一個，寫進每個檔案，遊戲顯示的就是它。你確認過的譯文不會被換掉，其他檔案會跟著你的。

**特殊情況**
- **整合包改過名稱的文字：** 整合包用 KubeJS 或資源包把物品改名時（例如 Iron Sword 改成 Rusty Blade），只採用符合新名稱的來源，不會被參考庫翻回原名。
- **重新翻譯同一包：** 上次套用的譯文會記住原本的來源，重跑時照樣標示「AI 補譯」「簡中轉繁」等，不會被當成模組原本附的繁中，也不會再被改寫。

### 5. 都找不到時，判斷是否根本不用翻

只有在所有來源都查不到中文時才判斷；只要任何來源有中文，就一定用中文。以下保留原文，列為「無需翻譯」，也不送給 AI：

- 參數與符號（`%s`）、單位（`mB`、`°C`、`bar`）、尺寸（`64 x 64`）、羅馬數字、色碼
- 按鍵（`Shift`、`Ctrl + Shift`）、技術縮寫與標籤（`NBT`、`FPS: %s`）、座標（`X: %d`）
- 模組、平台與品牌名稱（`Patreon`、`CurseForge`）、作者名、歌曲的「作者 - 曲名」、`Boss`（官方繁中也直接寫 Boss）
- 開發者註解、字型預覽範例句、書本樣板變數（`#name`）、指令用法、檔案路徑與 ID

其餘仍缺中文的，才會交給 AI（若有勾選）或留在報告的「缺少中文來源」。

### 6. 檢查每一筆譯文

逐筆比對原文和譯文的參數、格式碼、換行與數字，不一致的不採用。任務書的連結行只允許改顯示的文字，連結目標不能變。

- **顏色代碼（`§a`、`&6`）：** 用到的顏色要和原文相同；中文語序常需要在名稱後面把顏色切回來，所以出現幾次不必相同。
- **書本代碼：** 連結、按鍵、提示這類有目標的（例如 `$(l:items/aura_cache)`）一個都不能少；只改外觀或自動帶入詞的（`$(item)`、`$(aura)`）可以多用或少用。
- **參數（`%s`、`%d`）：** 數量和種類要相同。中文語序需要對調時，程式會自動加上編號（`%2$s … %1$d`），遊戲會把值放到正確位置。

- **換行數不同：** 中文通常比英文短，行數常常對不上。這時程式會依原文每行的比例、在標點處重新斷行，其他文字完全不變；AI 的譯文、簡中轉繁的譯文和你自己在報告裡修改的譯文都一樣，不用自己數換行。
- **其他格式問題：** 送給 AI 時會列出每一個必須照抄的代碼；AI 的回答還是不符時，同一次工作內會帶著退回原因再問一次，還是不行才留在「缺少中文來源」。被退回的 AI 譯文會保存在那一筆，雙擊就能看到；確認時若仍不符，會直接告訴你少了哪個代碼。
- **AI 判斷不需要翻的：** 例如模組名稱、色碼，會放到「無需翻譯」並寫出 AI 的理由，之後也不會再問一次。

### 7. 備份後套用

- **分兩次寫入：** 第一次寫入參考來源翻好的部分；有勾選 AI 時，AI 補翻和核對完成後再寫入第二次。第一次被遊戲或其他程式擋住時，AI 做完會再試一次；還是不行就保留全部譯文，關閉遊戲後按「重試套用」。
- **備份：** 先確認硬碟空間足夠，再備份所有要修改的原檔，然後寫入，寫完後重新掃描確認。空間不夠時不會開始寫。
- **模組語系檔的文字：** 放進程式產生的資源包 `resourcepacks\MCTranslator-zh_tw.zip`，並自動在遊戲設定裡啟用、排在最上面（OpenLoader 資料夾和模組自動產生的資源包也一起排在它下面，避免遊戲啟動時把它們放到翻譯上面）。這類語系文字不修改模組檔，所以 CurseForge 啟動遊戲或檢查檔案時不會把翻譯洗掉。內嵌在模組裡的函式庫（jar-in-jar，例如 ponder、flywheel）的文字也放在這裡。
- **Patchouli 書本的書名與首頁介紹：** 有些模組把英文直接寫在書本設定（`data/.../book.json`）裡，資源包蓋不到那個檔案；但 Patchouli 顯示時會先拿這句英文去查語系檔，所以程式把「這句英文 → 中文」寫進翻譯資源包，模組檔一樣不修改。
- **Whispering Quests 的任務：** 放進程式產生的資料包 `config\openloader\data\zz-MCTranslator-zh_tw.zip`（需要整合包有 OpenLoader），模組檔不修改；還原時整個資料包刪除。格式 3 只分享已套用的任務文字，安裝補丁時以對方自己的原始任務檔重建；不分享任務檔的完整複本。
- **KubeJS、CraftTweaker、設定檔、任務檔、槍械包等：** 直接寫入各自的檔案。槍械包缺少繁中語系檔時，會在該槍械包裡新增 `zh_tw.json`（還原時刪除）。
- **遊戲語言：** 有勾選才會改成繁體中文；沒勾選時，套用後請在遊戲的「選項 → 語言」選擇繁體中文（台灣）。

### 同一個東西翻得不一樣時

「譯名與用詞」頁會列出物品、方塊、生物等**名稱**在不同模組翻得不一樣的情況，例如棕櫚原木在一個模組叫「棕櫚原木」、另一個叫「棕櫚木原木」。

- **只看名稱：** 通用介面詞（例如 None、Default）在不同情境本來就可能不同，不會列出。
- **判定「同一個東西」：** 英文相同、語系鍵結尾也相同才算。牆上的火把和一般火把這種不同的東西不會被合併。
- **自動推薦：** 依上面「每一句依序找中文」的同一套順序推薦（你確認過的 → 台灣翻譯組人工繁中 → 模組繁中 → 官方譯名 → 簡中轉繁），同等級再比出現次數。
- **自動統一：** 「一鍵完整翻譯並套用」會直接統一成建議譯名，並保留原本譯名和修正紀錄。想改成別的，到「譯名與用詞」頁改選即可。

### 8. 寫入後核對，算出完成率

寫入後，程式會回頭讀一次遊戲實際讀取的檔案（翻譯資源包、任務檔、KubeJS…），確認每一句真的是剛寫進去的中文；翻譯資源包沒有啟用時，裡面的句子不算。首頁的兩個數字就是這樣算出來的：

- **中文化完成率：** 程式找得到的玩家文字裡，遊戲會顯示成中文的比例。無條件捨去，只有全部都是中文才會顯示 100%。模組名稱、代碼這類「無需翻譯」不算在內；程式內部字串無法確認遊戲會不會顯示，也不算在內，另外寫出條數。
- **還缺中文：** 還是英文的句數，底下寫出原因（找不到中文來源、寫在模組程式裡等）。這個數字是 0，才代表找得到的玩家文字都翻完了。
- **這次的效果：** 進度區會寫「這次從 82.1% 提升到 97.3%」；重跑同一個整合包沒有新東西時，會寫「和翻譯前一樣，這次沒有修改任何遊戲檔案」。寫入的句數不代表翻完沒，所以不放在首頁的大數字。

程式還沒支援的檔案格式不在計算範圍內，100% 代表「程式找得到的文字都是中文」，不保證遊戲每個角落都沒有英文；看到英文請回報。

### 9. 報告

「一鍵完整翻譯並套用」已直接套用所有通過檢查的譯文。報告開頭先回答四件事：**已套用幾筆、哪些沒套用和原因、哪些建議確認、備份在哪裡**；譯文來源明細收在「顯示譯文來源明細」。報告是讓你確認不確定的翻譯：

- **建議確認：** 列數值和原文不同、名稱和原文或地圖不一致、版本未確認、原文顯示格式已修正，以及 AI 改寫未通過檢查等具體疑點。不因來源是 AI、自動統一譯名或已修正用字，就要求逐筆人工確認；來源與修正紀錄仍保留，沒有改標成人工確認。
- **修正方式：** 雙擊修正後按「確認這筆」，程式會記住，下次翻譯自動使用。
- **一次確認很多筆：** 先用篩選或搜尋列出想確認的譯文（建議一次一個模組），按「確認目前列出的全部」。確認過的譯文順位高於社群參考庫，所以請看過再按；確認錯了可以按「取消上次整批確認」。
- **請 AI 核對：** 「AI 核對疑點」會把數值不同、版本不同的譯文，以及留有英文或生態域叫法和地圖不同的結構名稱，交給 AI 對照英文核對。正確的記下「AI 已核對」並移出「建議確認」；有錯的改寫成「AI 補譯」，要再按一次「備份並套用譯文」才會寫入。
- **不用逐筆確認：** 報告頁的「備份並套用譯文」會一次套用所有通過檢查的譯文；只有想修改的才需要雙擊。

篩選分成「已翻譯」（依翻譯方式：台灣參考庫、模組繁中、官方譯名、簡中轉繁、AI 補譯等）和「未翻譯」（缺少中文來源、無法確定是否顯示、無需翻譯），每筆都顯示所在的檔名，方便到資料夾找。程式內部字串（記錄檔訊息、程式碼、識別字）會自動和「無法確定是否顯示」分開，只留下值得檢查的；模組程式裡確定只拿來丟錯誤或寫記錄檔的句子（例如「Registry does not exist!」）也會分到「無需翻譯」，只要有一處可能顯示給玩家就仍留在待查。

「無法寫入（遊戲中是英文）」是遊戲會顯示、但這個整合包寫不進去的文字，多半寫死在模組程式裡：資源包蓋不過去，CurseForge 又會把改過的模組換回原版，所以遊戲中出現時是英文；程式裡本來就是中文的不列在這裡。「寫入後遊戲讀不到」是寫入後從遊戲讀取的檔案回讀，卻沒有這句的文字（例如資源包沒有啟用）。兩個模組帶了同一個書頁檔時，遊戲只會顯示其中一份，只要那一份是中文，兩句都算已是中文。

「還缺中文」的句數一定等於「缺少中文來源」「無法寫入」「寫入後遊戲讀不到」三個分類，加上已翻好、還沒寫入的句數（這些仍列在已翻譯的分類裡）。報告頁上方的「中文化完成率」「還缺中文」和開始頁是同一組數字。

模組 data 資料夾裡的語系檔（data/模組/lang/）是給伺服器用的：Forge 只讀那裡的英文，不會讀繁中，畫面上的同一句來自 assets 資料夾裡的語系檔，已在那裡翻譯，所以不列入、不算缺。數字檢查會把英文月份當成數字（December 等於 12 月），翻成「12 月」不會被當成改動了數字。

**換行：** 模組作者、翻譯組或你自己寫的中文，行數比英文少時保留原本的斷行，不再硬切成英文的行數（舊版曾把「魚肉鮮嫩麻辣」切在「麻／辣」之間，下次執行會改回來）；AI 的譯文仍依英文行數排好。

## 已翻譯整合包：直接安裝別人翻好的整合包

不用再從雲端下載檔案、自己複製到 CurseForge 資料夾。

1. 打開「已翻譯整合包」頁，會列出已發布翻譯的整合包。每張卡片都有兩組資訊：
   - **整合包版本與發布日期**：整合包本身的版號，例如「整合包版本 1.1.1a（2026-09-18 發布）」。
   - **翻譯版本與更新日期**：同一個整合包版本的翻譯改進後會重新發布，例如「翻譯第 2 版・2026-09-29 更新」。
2. 按卡片上的按鈕：
   - **安裝整合包與翻譯**：電腦上還沒有這個整合包時出現。按下後 CurseForge 會跳出來下載整合包（請在它的視窗確認），程式會自己等它裝好，接著裝上翻譯、把遊戲語言設成繁體中文。安裝時會開一個進度視窗，寫明現在是第幾步：CurseForge 顯示裝好後翻譯還要再裝一段時間，這時進度視窗會跳到最前面並發出 Windows 通知，看到「翻譯已安裝」才算完成，在那之前請不要開遊戲。等待途中可以按「停止等待」。裝好後卡片會自動變成「重新安裝」，不用按重新整理。
   - **安裝翻譯**：電腦上已經有這個整合包時出現。程式會自己找到整合包（裝在自訂位置也找得到），先備份再安裝。
   - **翻譯者加裝的模組**：翻譯者在整合包之外用 CurseForge 加裝的模組（例如解決輸入法卡住的 IMBlocker）會列在卡片上。安裝時確認一次就會一起加入：程式從 CurseForge 的官方檔案伺服器下載，確認和翻譯者用的是同一個檔案才放進模組資料夾，之後可在「備份與還原」移除。
   - **翻譯者的伺服器**：卡片寫著伺服器名稱和位址時，安裝或重新安裝會把它加在「多人遊戲」伺服器清單的最上面，點兩下就能連線（清單裡已經有同一個位址就不重複加，可在「備份與還原」移除）。位址是 26 開頭（Radmin VPN）或 25 開頭（Hamachi）時，要先加入翻譯者的那個網路才連得上；伺服器要開著才能進去。
   - **怎麼調整記憶體**：列出在 CurseForge 調整的步驟。卡片會顯示整合包作者建議的大小；作者沒有寫時，改依模組數估一個大小並標明「程式估計，不是作者建議」。你的電腦記憶體分完後剩不多時會提醒。
3. 有新上架的翻譯時，側欄的「已翻譯整合包」後面會出現數字（新上架和有更新的總數，滑鼠移上去可看明細）；新上架的正好是你電腦上的整合包時會跳出 Windows 通知。之後翻譯有更新，卡片會標示「翻譯有更新」，按「更新翻譯」即可。

**整合包版本不同時**
- 每個整合包只有一張卡片。程式會挑出和你安裝的整合包版本相同的那一份翻譯，舊版本的翻譯也會保留；有更新版本的翻譯時，卡片會多一行提示。
- 如果沒有你的版本，可以按「仍要安裝」，只翻譯和當時完全相同的模組，其他的略過、不會覆蓋；略過的部分再按一次「一鍵完整翻譯並套用」補齊即可。

翻譯只含文字，不含模組程式或整個模組檔。v0.32.0 的新補丁可以分享已套用的主選單英文翻譯、結構中的 NPC／告示牌文字、資料包任務、光影語系，以及已證明只用於顯示的程式字串。補丁只記原句、譯文與原檔校驗碼；接收端重新掃描自己的原檔，確認同版本、用途與格式後才重建並寫入，不使用 AI。新內容需 v0.32.0，舊格式補丁仍可安裝。社群譯文依各來源授權免費分享。

按下「安裝」後不需搬檔或重新翻譯。結果會區分分享內容通過檔案核對、只安裝部分內容，以及舊補丁缺少一致性資料；分享者匯出時略過的內容、缺少的模組與版本不符都會明列。這是檔案檢查，仍不能代表遊戲畫面已全部驗收。用途未確認的轉換、Mixin 涉及的 class 與 CurseForge 會換回的程式文字不分享。

NPC 名字、建築告示牌與書本若已生成進舊存檔，照字面保存的舊文字可能仍是英文。補丁會翻譯之後新生成的來源，**不修改存檔、交易或任務進度**；使用語系鍵的既有內容則可隨語系翻譯更新。

**整合包和翻譯各從哪裡來**
- **整合包（模組、設定）：** 由 CurseForge 從官方下載，本程式不提供也不散布模組檔。所以電腦要先裝好 CurseForge。
- **翻譯者加裝的模組：** 翻譯裡只記下是哪一個模組的哪一個檔案和它的校驗碼。你選擇加入時，程式從 CurseForge 的官方檔案伺服器下載，確認和翻譯者用的是同一個檔案才放進模組資料夾；不符就不安裝。加入的模組會列在「備份與還原」，還原就會移除。
- **不會自動加入的模組：** 作者只開放由 CurseForge 安裝的、不是從 CurseForge 裝的、你已經裝了別的版本的，都不會動，完成時會列出來並說明怎麼自己加裝。翻譯者把整合包原有的模組換成別的版本時，你保留整合包的版本。
- **翻譯：** 只有繁體中文文字，放在本專案的 GitHub，約幾 MB。
- **記憶體：** 卡片和安裝完成的訊息會顯示整合包作者建議的記憶體大小（取自整合包的 manifest.json；作者沒寫時依模組數估計並標明是估計），按「怎麼調整記憶體」看 CurseForge 的設定步驟。程式只讀取 CurseForge 目前的設定，不會修改；請在 CurseForge 自行調整。

**下載的翻譯裡有什麼、沒有什麼**
- **有：** 繁中語系檔、書本與已支援文字的逐句修改。翻譯資源包／資料包從你的原檔重建；結構、程式與設定不帶完整檔案。機器識別值、配方內容與任務獎勵不能由補丁更改。
- **沒有：** 模組檔、設定檔、記憶體和啟動器設定、存檔。安裝翻譯只會在遊戲選項（`options.txt`）裡啟用翻譯資源包，有勾選時也把語言設為繁體中文。翻譯者加裝的模組只有名稱和校驗碼，檔案本身不在裡面。
- **翻譯者另外加裝的模組：** 安裝確認列出的 CurseForge 模組會一起下載；沒有可信下載來源或版本不同的保留原狀，結果明列，因此不會宣稱雙方內容一致。

### 不在 CurseForge 上的整合包（整包安裝，v0.22.0 起）

v0.36.0 起，整包安裝與更新也支援卡片指定的伺服器：確認視窗會列出名稱與位址，安裝後加入多人遊戲清單，不重複加入同位址，原清單保留，變更可在「備份與還原」復原。清單讀不懂時保留原樣並說明。之後新上架的整合包預設加入「狗狗貓貓島」（26.186.50.26），需先加入分享者的 Radmin VPN 網路且伺服器已開啟才能連線；不會自動加入 VPN 或啟動伺服器。

有些整合包是從其他啟動器搬過來的，CurseForge 上沒有，卡片會寫「這個整合包不在 CurseForge 上」。這類整合包由分享者整包放在 Google 雲端，按一次「安裝」並確認後：

1. 從分享者的 Google 雲端下載整合包（已含繁體中文翻譯）；中斷時再按一次會接著下載。
2. CurseForge 上找得到、而且和分享者一模一樣的模組，從 CurseForge 官方檔案伺服器下載；其餘的在壓縮檔裡。
3. 每個檔案都要和分享者的內容清單（路徑與校驗碼）相同，有任何不同就不安裝。
4. 在 CurseForge 的整合包資料夾新開一個資料夾（同名時加 (2)），並把它加進 CurseForge 的整合包清單。這一步 CurseForge 必須是關閉的，程式會提醒你並等待；寫入前會先備份 CurseForge 的清單，出錯就還原。

裝好後在 CurseForge 的「我的建立」找到它就能玩。壓縮檔不含分享者的存檔、地圖紀錄、帳號、伺服器清單和個人遊戲設定（遊戲選項只帶語言和資源包清單）。不想要時在 CurseForge 對它按右鍵刪除。安裝進度會顯示在那張卡片上；CurseForge 開著時，按下安裝就會先提醒，等到要關掉 CurseForge 的那一步會跳出 Windows 通知。

v0.36.3 起，即使總清單與獨立版設定檔都找不到，只要預設的 curseforge/minecraft/Instances 下已有有效的 CurseForge 整合包設定檔，仍能辨識安裝位置並繼續安裝。會核對設定檔的 GUID、遊戲版本、載入器、模組清單、實際資料夾與紀錄路徑，不把空資料夾或其他啟動器的資料夾當成 CurseForge。這條修復共用於所有雲端整包，不只 Elemental Awakening。

v0.36.2 起，安裝整包會優先使用 CurseForge 已設定的 Minecraft 遊戲資料夾。即使 Minecraft 整合包總清單尚未產生，只要遊戲資料夾設定與 Instances 資料夾存在，仍可下載、核對並建立新整合包的設定檔；重新開啟 CurseForge 後由它載入，不建立空的總清單、不改其他整合包。有總清單時仍先備份、只加入一筆。找不到有效的遊戲資料夾設定及總清單，或現有總清單格式不正確時，會在下載前停止並說明。

舊版曾把已安裝的翻譯誤報為「部分翻譯」。重新整理已翻譯整合包頁時，程式會在背景用保留的補丁核對目前檔案、譯文與資源包啟用狀態，全部符合才更新卡片狀態，不會重新翻譯或修改遊戲。補丁已刪除、缺少模組、內容不同或未啟用時保留原狀，可按重新安裝查看結果。

**更新（v0.23.0 起）：** 分享者更新後卡片會顯示「有新版本」，按「更新整合包」直接更新原本的設定檔，不另外建一個。只換掉有變動的檔案、移除新版本拿掉的模組；存檔、遊戲設定（options.txt）和截圖不動；換掉和移除的檔案先備份，可在「備份與還原」復原。你改過但新版本拿掉的檔案不會刪除。更新時 CurseForge 不必關閉，只要關掉這個整合包的遊戲。名稱裡的版本號不同（例如 The Foll v0.3.0 → v0.4.0）仍視為同一個整合包。

**注意：** 這種方式會把整合包裡別人做的模組與設定一起分享出去，可能不符合模組或整合包作者的授權；是否上架由分享者自行決定並負責。Google 雲端在短時間內被很多人下載時會暫停一陣子，請晚點再試。

### 建立伺服器

電腦上已經有這個整合包時，卡片上會有「建立伺服器」。按下後：

1. 選擇或貼上要放伺服器的資料夾（例如 `C:\Users\你的名字\Desktop\Minecraft server`），程式會在裡面新開一個「整合包名稱 Server」資料夾，不會動到裡面原有的伺服器。
2. 確認一次內容，再同意 Minecraft 的使用者授權合約（EULA）。EULA 必須由你本人同意，程式不會代按。
3. 程式自動完成：
   - 複製 mods、config、kubejs、defaultconfigs 等伺服器需要的資料夾（翻好的任務、設定文字也一起帶過去）。存檔、材質包、光影和遊戲選項不複製，整合包本身不會被修改。
   - 從 NeoForge／Forge／Fabric 官方網站下載對應版本的伺服器程式，核對官方校驗碼後才安裝。
   - 自動試開伺服器。只給玩家端用的模組（例如 IMBlocker、Sodium、小地圖）會讓伺服器當掉，程式從當機紀錄找出是哪一個，移到「_已拿掉的模組」資料夾（不刪除），再重開，直到開得起來。
   - 寫好 `run.bat` 和記憶體設定。記憶體依模組數量設定上限（以 1～10 人、同一台電腦也要開遊戲和其他遊戲來估算），可在 `user_jvm_args.txt` 修改。
4. 完成後雙擊 `run.bat` 就能開伺服器。拿掉了哪些模組和原因、朋友怎麼連線，都寫在資料夾裡的「伺服器說明.txt」。

限制：
- 當機原因不是玩家端模組時（例如 KubeJS 腳本錯誤、模組本身的錯誤、整合包缺少前置模組），程式不會亂拿東西，會停下來說明是哪個模組出了問題。
- 試開只能確認伺服器開得起來；少數模組要等玩家進遊戲才出錯，遇到時請看伺服器資料夾的 `crash-reports`。
- 目前支援 NeoForge、Minecraft 1.17 以上的 Forge 和 Fabric；Quilt 還不支援。Fabric 模組自己標明只給玩家端用（environment 為 client）的會先拿掉。需要電腦上有對應的 Java（用 CurseForge 開過這個整合包通常就有）。
- 朋友從其他地方連線，需要在路由器設定連接埠轉發 25565，或使用 Radmin VPN、ZeroTier 這類工具，程式無法代為設定。

## AI 補翻（選用）

不登入也能翻譯；AI 只做兩件事：補參考庫找不到的部分，以及核對有具體疑點的譯文（數值和原文不同、來自其他版本、名稱留有英文或和地圖用詞不同）。

**讓翻譯越用越準**
- **你確認過的最優先：** 在報告裡確認或修正的譯文會記住，之後翻譯任何整合包，同一個模組的同一句直接使用。
- **AI 翻過的會記住：** 沿用時仍標示「AI 補譯」、順位最後，不會蓋過參考庫或你確認的內容。
- **不會自己學：** 程式不會從沒確認過的譯文學習；沒確認的每次都重新依來源順序挑選，所以多確認才會越來越準。

- 在「AI 帳號與模型」按「安裝官方元件」→「連接 ChatGPT」，在官方網頁登入。
- **會消耗你 ChatGPT 方案的 Codex 額度**（與其他 Codex 工作共用），不使用 API key、不另外收費、不會自動加購。額度不足時會停止並保留已完成的部分。
- 只傳送缺漏的原文、語系鍵與模組內路徑；核對疑點時另外傳送那一筆目前的譯文和疑點說明。不傳整個模組包或存檔。
- AI 譯文會標記為「AI 補譯」，建議抽查。
- **選模型：** 「AI 帳號與模型」頁列出帳號可用的模型，並附上官方說明（已知的說明會顯示繁體中文，滑鼠移上去可看官方原文）、推理強度，以及是否有專屬額度。
- **建議模型：** 程式會標示「建議」的模型，沒有自己選過時預設就用它。建議的依據是官方說明：遊戲文字多是短句，所以選官方描述為快速、省額度、而且額度還能用的模型；沒有這類模型時建議官方預設。你自己選過的模型會被記住，不會被建議蓋掉。官方沒有提供翻譯品質或確切耗量數字，所以這不是品質排名。
- **額度判斷：** 只看 Codex 額度和你選的模型的專屬額度；其他模型的額度用完不會影響你。
- **省額度：** AI 只補參考來源找不到的文字（以 Tensura 為例約 2.4%）。一次送出最多 60 句；補翻時會依實際用量推算剩下還需要多少額度。同一個檔案裡相同的原文只送一次，其他幾筆用同一句譯文，用詞一致也不重複花額度；不同模組的相同英文仍分開送。
- **速度：** AI 補翻與核對會同時送出 2 批，等待時間大約減半，總共消耗的額度不變。額度剩 20% 以下時改回一次一批；官方服務不接受同時送出時，也會自動改回一次一批，不會漏掉或重複送出。
- **額度不夠時：** 在剩 5% 時暫停（每次送出前檢查，同時送 2 批時最多多跑兩批），已完成的 AI 譯文和其他所有譯文照常套用；額度恢復後再按一次「一鍵完整翻譯並套用」，只會補剩下的。

## 整合包更新後

CurseForge 更新整合包時，模組的新版本可能加了新的文字，翻譯資源包裡也可能留著舊版本的譯文。程式開啟時會比對整合包版本；發現翻譯過的整合包已更新，「開始翻譯」頁頂端會提醒，可以直接按「重新翻譯並套用」或「查看已翻譯整合包」。

## 備份與還原

每次套用前，會把要修改的原檔備份到 EXE 旁的 `MCTranslatorData\output\<模組包>\原始備份\`。「備份與還原」頁可以一鍵還原某一批；如果檔案之後被你改過，會先停下來說明，不會覆蓋。

- **套用到一半當機或斷電：** 下次開啟程式會提醒。到「備份與還原」選標示「中斷」的那一批按還原：還是原樣的檔案不動，已經寫入的檔案還原。
- **還原順序：** 同一個檔案（例如翻譯資源包）被兩批翻譯改過時，要先還原較新的那一批；程式會告訴你是哪一批。
- **佔用空間：** 程式會自動清掉自己的暫存檔、舊的參考庫下載、舊的更新下載檔，舊版程式只留最近一個。備份和報告不會自動刪除。

## 更新

開啟程式時會檢查新版，有新版會在右上角提示，**由你決定何時下載安裝**。更新會先驗證檔案，失敗時保留舊版；翻譯紀錄、備份與設定都會保留。GitHub 查詢次數用完時，會改從公開的發布頁確認版本，驗證方式不變。

> 從 v0.4.0 或更舊版本升級時，畫面可能停在「準備重新啟動」。請手動關閉程式，更新會在 2 分鐘內完成並自動開啟新版。v0.4.1 起已修正。每一版的更新內容會直接顯示在「程式更新」頁。

## 目前限制

- 圖片裡的文字、程式寫死的文字、部分動態組句不一定能翻；這些會列在報告的「無法確定是否顯示」。
- 在 CurseForge 的整合包裡，寫在模組程式裡的文字（不在語系檔裡的）無法保留翻譯，因為 CurseForge 啟動時會把改過的模組換回原版；報告會列出這些文字。例外是能確認語系鍵的設定說明，會放進翻譯資源包，只在遊戲內設定畫面顯示中文。
- 內嵌函式庫資料夾（`data/`）裡的書本頁資源包蓋不過去，在 CurseForge 整合包裡不會寫入。
- 遊戲裡如果自己關掉「MCTranslator-zh_tw」資源包，模組的翻譯就不會顯示；再按一次「一鍵完整翻譯並套用」會重新啟用。
- 自動檢查只確認格式、參數與數值沒被改壞，不保證每句語意都正確。
- 移動 EXE 時請連同 `MCTranslatorData` 資料夾一起移動；這個資料夾含有登入資料，不要分享給別人。
- 數值檢查只比對數字有沒有少或不同，判斷不了完整語意；未解決疑點會在完成提示列出，不會因流程跑完就當成已解決。
- AI 核對不是人工確認：AI 判斷「無誤」的譯文會移出「建議確認」，但 AI 也可能看錯，重要的內容仍建議自己抽查。
- 由模組推測 Minecraft 版本可能不準，推測時報告會註明；建議從啟動器清單選擇整合包。
