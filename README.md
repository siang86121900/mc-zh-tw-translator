# MC Translator · 模組包繁體中文化

把 Minecraft 模組包（模組、任務、Patchouli 等書本、KubeJS、設定檔）翻成台灣用語的繁體中文，並在套用前自動備份原檔。

## 下載與使用

從 [最新版下載頁](https://github.com/siang86121900/mc-zh-tw-translator/releases/latest) 下載 `MCTranslator.exe`，雙擊即可，不需要安裝 Python。

1. **關閉遊戲**，從下拉清單選擇模組包（會自動列出 CurseForge、Modrinth、Prism、MultiMC、ATLauncher 的模組包和你用過的資料夾）。找不到時可直接貼上路徑，或按「選擇資料夾」。選到模組包裡的 `mods` 之類的資料夾也沒關係，程式會改用模組包本身；選到放了好幾個模組包的外層資料夾，會請你選其中一個。
2. （選用）勾選：
   - 「用 AI 補翻缺漏，並核對有疑點的譯文」：需要先在「AI 帳號與模型」連接 ChatGPT
   - 「套用後把遊戲語言設為繁體中文」：修改 `options.txt`，一樣會備份、可還原；不勾就自己在遊戲裡切換
3. 按 **一鍵完整翻譯並套用**，等它跑完。
4. 重新啟動遊戲，語言選「繁體中文（台灣）」。

遊戲沒關也沒關係：譯文和報告會先保存，關掉遊戲後按「重試套用」即可，不用重新翻譯。啟動器可以開著：寫入時若檔案剛好被啟動器或防毒軟體打開，程式會稍等並自動再試。跑完時會跳出 Windows 通知，工作列圖示也會顯示進度。

## 翻譯邏輯

按下「一鍵完整翻譯並套用」後，程式依序做這些事。參考來源能翻的會先寫入遊戲（通常幾分鐘），這時遊戲已經是中文；AI 補翻比較慢，做完再寫入第二次。

### 1. 確認參考庫是最新版

- **必須是最新：** [ModsTranslationPack](https://github.com/TeamKugimiya/ModsTranslationPack)（繁中）與同版本 [CFPA](https://github.com/CFPAOrg/Minecraft-Mod-Language-Package)（簡中）。確認不到就停止，不會拿舊資料冒充。
- **怎麼確認：** 用沒有次數限制的方式向 GitHub 確認，網路不穩會自動重試最多 3 次；GitHub 的查詢服務（同一個網路每小時 60 次）只當備援。
- **Minecraft 版本：** 先讀啟動器的紀錄；啟動器沒有記錄時，從已安裝模組的需求推測，並在報告註明。
- **補充來源：** [ParaTranslationPack](https://github.com/TeamKugimiya/ParaTranslationPack)、CFPA 1.20／1.19／1.18、Minecraft 官方繁中。暫時取不到時只略過並記在報告。
- 使用的版本、下載時間與雜湊都會記在報告裡。

### 2. 掃描整個模組包

讀取 `mods`（含內嵌在模組裡的函式庫）、資源包、資料包、KubeJS、設定檔、任務與 Patchouli 等書本，找出所有玩家看得到的文字。沒變動的模組會沿用上次的掃描結果。

同一段文字並列多種語言的設定（例如 Ponderer 動畫教學的 `config/ponderer/scripts`，每段同時寫著英文和簡中）會在旁邊加上繁中；整合包作者的英文有時沒寫完，這時以完整的簡中轉成台灣用語。只有確認過模組會讀繁中的格式才會寫入，其他的列在報告並註明原因。

FTB 任務書的文字（`config/ftbquests/quests/lang/` 裡的 `.snbt`）會逐行翻譯：整合包附的簡中任務檔會先轉成台灣用語，對不上的行再交給 AI，最後寫出繁中任務檔 `zh_tw.snbt`。英文任務檔不會被修改，圖片與換頁指令原樣保留。

任務文字直接寫在任務章節檔裡的整合包（FTB Quests 1.20.1，例如 The Foll），以及設定檔（`config`、`defaultconfigs`）和 KubeJS 腳本裡直接寫的中文：簡體字會在原檔轉成台灣用語，只改那段文字，其餘內容與排版不動，一樣先備份、可還原。設定的名稱（鍵名）、註解行、其他語言專用的檔案（例如 `lang/zh_cn.json`）不會改；整合包留著、遊戲不讀的 `quests-backup` 也不改、不計數。

設定說明與寫在模組程式裡的句子也會翻譯：目前支援能確認全部用途的 Forge／NeoForge 設定說明，以及直接傳給 Minecraft 顯示文字呼叫的常數，例如 AppleSkin 的「按住 SHIFT 顯示食物數值」說明。選用 AI 並同意後會補翻，沿用相同的額度保護、檢查、備份與還原流程；傳送範圍包含這些句子、文字位置與模組內相對路徑。重跑會認出已套用文字，保留 AI 來源。

這類文字通常只能寫回原模組。CurseForge 在啟動遊戲時會把它自己裝的模組檔換回原版，所以這些模組的這類文字不寫入、也不花 AI 額度，報告會寫明原因。你自己放進 mods 資料夾的模組（不是從 CurseForge 裝的）CurseForge 換不回去，會和其他啟動器一樣寫回原模組；模組程式裡寫死的簡體字也會轉成台灣用語。需要時可從備份還原。

例外是遊戲內設定畫面（模組清單的「設定」）顯示的設定說明：NeoForge 內建的設定畫面和 Configured 會先到語系檔找「設定的語系鍵.tooltip」，找不到才顯示程式裡的英文。所以在 CurseForge 整合包裡，能確認語系鍵的設定說明會翻譯並放進翻譯資源包，模組檔不修改。能確認的情況有兩種：模組替設定取了語系鍵（Forge、NeoForge 都適用，NeoForge 內建畫面與 Configured 都會讀），或模組使用 NeoForge 內建設定畫面（語系鍵是「模組 ID.configuration.設定名稱」）。模組沒取語系鍵、又不是用 NeoForge 內建畫面的（例如只靠 Configured 或 ForgeConfigScreens 顯示），畫面只會顯示程式裡的英文，仍列在「無法寫入（遊戲中是英文）」。這個做法只改遊戲內設定畫面，config 資料夾裡設定檔的註解仍是英文。一段說明分成好幾行時，要每一行都翻好才一起寫入。同一句說明在模組程式裡出現兩次（同一個語系鍵、同一句英文）時，會統一成最可信的一種譯法再寫入，你確認過的說法優先；原文不同的才會列出原因、不互相覆蓋。模組語系檔本來就有這句說明的，交由一般語系流程翻譯，也不會重複算進「還缺中文」。報告的搜尋也能搜尋疑點文字。目前含 class 修改的模組會被分享補丁匯出檢查擋下，不會散布程式檔。程式判斷用字串、公開常數、用途不明、註解標註或動態組句仍列為待查，不會只憑一句英文就直接替換。模組啟動後是否把說明更新到既有設定檔，取決於模組本身。

### 3. 先排除「遊戲不會顯示」的文字

- **沒安裝的模組：** 模組包附帶的整份翻譯包（例如放在 OpenLoader 的 CFPA）常含上千個沒安裝的模組，這些直接略過。別的模組為它準備的相容材質或配方，不算它有安裝；要有這個模組本身、它的語系檔或世界生成資料才算。
- **指向未安裝模組的名稱：** 例如 Traveler's Titles 裡其他模組的生態域名稱，也一併略過。

### 4. 每一句依序找中文，找到就停

原則是**最準確、最道地的台灣用詞**：
- 你親自確認的最優先。
- 人工寫的繁中優先於「簡中轉繁」，因為 OpenCC 轉不乾淨「設定／設置」「篩選器／篩檢程式」這類用語差異。
- 參考庫的繁中必須「英文和目前模組版本相同」才排在前面，避免用到舊版譯文。

| 順序 | 來源 | 說明 |
|---|---|---|
| 1 | 翻譯記憶 | 你在報告裡「確認這筆」校對過的譯文，綁定模組、語系鍵與原文 |
| 2 | 自訂譯名 | 你在「譯名與用詞」頁固定的譯名（整句相同才套用） |
| 3 | ModsTranslationPack | 台灣社群人工繁中；英文須確認與目前版本相同 |
| 4 | ParaTranslationPack | 台灣社群人工繁中；英文須確認與目前版本相同 |
| 5 | 模組包裡的繁中資源包 | 整合包作者安裝的 zh_tw 資源包 |
| 6 | 模組原本附的繁中 | 含簡體字的不採用；殘留的大陸用語（激活、添加、代碼、設置等）改成台灣用語並列入「建議確認」 |
| 7 | Mojang 官方繁中 | 原版物品、方塊、生物等官方譯名；整句比對只用在名稱，避免「Red」這類一般詞蓋掉模組自己的譯名 |
| 8 | 模組包裡的簡中 | KubeJS、OpenLoader、資源包的 zh_cn，轉成台灣用語 |
| 9 | 同一個模組附的簡中 | 轉成台灣用語 |
| 10 | CFPA（同版本） | 轉成台灣用語 |
| 11 | 版本待確認的參考庫繁中 | 英文和目前版本不同，或沒有英文可以比對，標示待核對 |
| 12 | 跨版本 CFPA | 1.20／1.19／1.18，標示「跨版本參考」並列為待核對 |
| 13 | 內建術語表 | 常用 Minecraft 名詞；官方有譯名的一律用官方的 |
| 14 | 含簡體字的既有繁中 | 轉成台灣繁體，標示待核對 |
| 15 | AI 補翻（選用） | 只補前面都找不到的；句子裡提到的物品會照用這包整合包已決定的譯名與你固定的譯名。同一個模組的同一句以前翻過就直接沿用，不再消耗額度 |

參考庫是資源包，在遊戲裡本來就會蓋過模組自帶的繁中，所以排在它之前。以 Tensura 為例，這個順序讓約 1 萬筆原本「簡中轉繁」或模組自帶的譯文，改用台灣翻譯組的人工繁中。

**簡中轉繁的寫法**
- **字形跟官方繁中一樣：** 寫「工作台」「基岩」「床」，不寫「工作臺」「基巖」「牀」。模組原本的繁中用了台、岩、床、群、峰，也不會被當成簡體。
- **修正常見的選錯字：** 一個簡體字可能對應好幾個繁體字，轉換工具遇到不認識的詞會選錯，例如松木變「鬆木」、最多只能變「最多隻能」、綁定變「繫結」、鐘石變「鍾石」；這些會自動改回來，模組自帶的繁中裡有同樣的錯字也會改正（「鍾愛」「情有獨鍾」不會被改）。
- **判斷是不是簡體字更準：** 「吃」「背包」「游標」「了解」「秘密」是台灣正常的寫法，不再被當成簡體字而降低模組自帶繁中的優先順序。
- **不改在台灣也正確的詞：** 例如「支持者」「質量」（重量）、「控制代碼」「錯誤代碼」、「數據機」「大數據」，以及「增加載入」這種剛好前後相連的字。
- **Minecraft 名稱用台灣官方譯名：** 簡中的「下界」「末影」「末地」「生物群系」「惡魂」「潛影」「刷怪蛋」等，依 Mojang 官方台灣繁中改成「地獄」「終界」「生態域」「地獄幽靈」「界伏」「生怪蛋」，「下界合金」改成「獄髓」。只換 Minecraft 專有的詞；「監守者」這種一般詞只在整句就是這個名稱時才換，模組自己的「地牢監守者」不會被改。舊版已寫入的這類用語會在下次執行時修正一次，並列入「建議確認」。
- **參考庫也一樣：** 台灣社群參考庫偶爾留著大陸用語（例如 Cloth Config 的「設置」），同樣改成台灣用語並列入「建議確認」，不會因為參考庫排序較前就蓋掉模組自帶的正確繁中。
- **數字不同只列出：** 模組自帶的繁中如果數字和英文不同（例如英文 30 秒、中文 15 秒），維持原文不改，但會列在「建議確認」的「數值和原文不同」。

**數值檢查**
- 譯文的數字和英文原文不同（例如原文「獲得 20 經驗」、譯文「獲得 10 點」），通常是中文來自模組的舊版本。
- 簡中轉繁、版本不同的來源遇到這種情況，會先改用數字正確的來源；都沒有才採用，並列入「建議確認」，寫出原文和譯文的數字。
- 中文數字（九十九、雙倍）和單位（1 萬＝10,000）不算不同。你確認過的譯文不檢查；模組為這個版本寫的繁中不會被換掉，只會列出。

**同一句出現在好幾個檔案時**
- 整合包常把同一個模組的同一句放在三個地方：模組本身、附帶的語言包（例如 OpenLoader 裡的 CFPA）、KubeJS。遊戲只顯示最上層的那一個。
- **只有中文、沒有英文的檔案：** 用已安裝模組的英文來比對和檢查；報告的「原文」欄顯示這句英文，滑鼠移上去可以看到檔案裡原本的中文。完全找不到英文時，參考庫的譯文不當成已確認。
- **每個檔案用同一個譯文：** 取來源最可靠的那一個，寫進每個檔案，遊戲顯示的就是它。你確認過的譯文不會被換掉，其他檔案會跟著你的。

**特殊情況**
- **整合包改過名稱的文字：** 整合包用 KubeJS 或資源包把物品改名時（例如 Iron Sword 改成 Rusty Blade），只採用符合新名稱的來源，不會被參考庫翻回原名。
- **重新翻譯同一包：** 上次套用的譯文會記住原本的來源，重跑時照樣標示「AI 補譯」「簡中轉繁」等，不會被當成模組原本附的繁中，也不會再被改寫。

### 5. 都找不到時，判斷是否根本不用翻

只有在所有來源都查不到中文時才判斷；只要任何來源有中文，就一定用中文。以下保留原文，列為「無需翻譯」，也不送給 AI：

- 參數與符號（`%s`）、單位（`mB`、`°C`、`bar`）、尺寸（`64 x 64`）、羅馬數字、色碼
- 按鍵（`Shift`、`Ctrl + Shift`）、技術縮寫與標籤（`NBT`、`FPS: %s`）、座標（`X: %d`）
- 模組、平台與品牌名稱（`Patreon`、`CurseForge`）、作者名、歌曲的「作者 - 曲名」、`Boss`（官方繁中也直接寫 Boss）
- 開發者註解、字型預覽範例句、書本樣板變數（`#name`）、指令用法、檔案路徑與 ID

其餘仍缺中文的，才會交給 AI（若有勾選）或留在報告的「缺少中文來源」。

### 6. 檢查每一筆譯文

逐筆比對原文和譯文的參數、格式碼、換行與數字，不一致的不採用。任務書的連結行只允許改顯示的文字，連結目標不能變。

- **顏色代碼（`§a`、`&6`）：** 用到的顏色要和原文相同；中文語序常需要在名稱後面把顏色切回來，所以出現幾次不必相同。
- **書本代碼：** 連結、按鍵、提示這類有目標的（例如 `$(l:items/aura_cache)`）一個都不能少；只改外觀或自動帶入詞的（`$(item)`、`$(aura)`）可以多用或少用。
- **參數（`%s`、`%d`）：** 數量和種類要相同。中文語序需要對調時，程式會自動加上編號（`%2$s … %1$d`），遊戲會把值放到正確位置。

- **換行數不同：** 中文通常比英文短，行數常常對不上。這時程式會依原文每行的比例、在標點處重新斷行，其他文字完全不變；AI 的譯文、簡中轉繁的譯文和你自己在報告裡修改的譯文都一樣，不用自己數換行。
- **其他格式問題：** 送給 AI 時會列出每一個必須照抄的代碼；AI 的回答還是不符時，同一次工作內會帶著退回原因再問一次，還是不行才留在「缺少中文來源」。被退回的 AI 譯文會保存在那一筆，雙擊就能看到；確認時若仍不符，會直接告訴你少了哪個代碼。
- **AI 判斷不需要翻的：** 例如模組名稱、色碼，會放到「無需翻譯」並寫出 AI 的理由，之後也不會再問一次。

### 7. 備份後套用

- **分兩次寫入：** 第一次寫入參考來源翻好的部分；有勾選 AI 時，AI 補翻和核對完成後再寫入第二次。第一次被遊戲或其他程式擋住時，AI 做完會再試一次；還是不行就保留全部譯文，關閉遊戲後按「重試套用」。
- **備份：** 先確認硬碟空間足夠，再備份所有要修改的原檔，然後寫入，寫完後重新掃描確認。空間不夠時不會開始寫。
- **模組的文字：** 放進程式產生的資源包 `resourcepacks\MCTranslator-zh_tw.zip`，並自動在遊戲設定裡啟用、排在最上面（OpenLoader 資料夾和模組自動產生的資源包也一起排在它下面，避免遊戲啟動時把它們放到翻譯上面）。模組檔本身完全不修改，所以 CurseForge 啟動遊戲或檢查檔案時不會把翻譯洗掉。內嵌在模組裡的函式庫（jar-in-jar，例如 ponder、flywheel）的文字也放在這裡。
- **KubeJS、設定檔、任務檔等：** 直接寫入各自的檔案。
- **遊戲語言：** 有勾選才會改成繁體中文；沒勾選時，套用後請在遊戲的「選項 → 語言」選擇繁體中文（台灣）。

### 同一個東西翻得不一樣時

「譯名與用詞」頁會列出物品、方塊、生物等**名稱**在不同模組翻得不一樣的情況，例如棕櫚原木在一個模組叫「棕櫚原木」、另一個叫「棕櫚木原木」。

- **只看名稱：** 通用介面詞（例如 None、Default）在不同情境本來就可能不同，不會列出。
- **判定「同一個東西」：** 英文相同、語系鍵結尾也相同才算。牆上的火把和一般火把這種不同的東西不會被合併。
- **自動推薦：** 依上面「每一句依序找中文」的同一套順序推薦（你確認過的 → 台灣翻譯組人工繁中 → 模組繁中 → 官方譯名 → 簡中轉繁），同等級再比出現次數。
- **自動統一：** 「一鍵完整翻譯並套用」會直接統一成建議譯名，並列入報告的「建議確認」。想改成別的，到「譯名與用詞」頁改選即可。

### 8. 寫入後核對，算出完成率

寫入後，程式會回頭讀一次遊戲實際讀取的檔案（翻譯資源包、任務檔、KubeJS…），確認每一句真的是剛寫進去的中文；翻譯資源包沒有啟用時，裡面的句子不算。首頁的兩個數字就是這樣算出來的：

- **中文化完成率：** 程式找得到的玩家文字裡，遊戲會顯示成中文的比例。無條件捨去，只有全部都是中文才會顯示 100%。模組名稱、代碼這類「無需翻譯」不算在內；程式內部字串無法確認遊戲會不會顯示，也不算在內，另外寫出條數。
- **還缺中文：** 還是英文的句數，底下寫出原因（找不到中文來源、寫在模組程式裡等）。這個數字是 0，才代表找得到的玩家文字都翻完了。
- **這次的效果：** 進度區會寫「這次從 82.1% 提升到 97.3%」；重跑同一個整合包沒有新東西時，會寫「和翻譯前一樣，這次沒有修改任何遊戲檔案」。寫入的句數不代表翻完沒，所以不放在首頁的大數字。

程式還沒支援的檔案格式不在計算範圍內，100% 代表「程式找得到的文字都是中文」，不保證遊戲每個角落都沒有英文；看到英文請回報。

### 9. 報告

「一鍵完整翻譯並套用」已直接套用所有通過檢查的譯文。報告開頭先回答四件事：**已套用幾筆、哪些沒套用和原因、哪些建議確認、備份在哪裡**；譯文來源明細收在「顯示譯文來源明細」。報告是讓你確認不確定的翻譯：

- **建議確認：** 只列已套用但值得看一眼的：AI 補譯、版本待確認的參考譯文、自動統一的譯名、數值和原文不同的譯文、改過用語的模組繁中。一般簡中轉繁不列入。
- **修正方式：** 雙擊修正後按「確認這筆」，程式會記住，下次翻譯自動使用。
- **一次確認很多筆：** 先用篩選或搜尋列出想確認的譯文（建議一次一個模組），按「確認目前列出的全部」。確認過的譯文順位高於社群參考庫，所以請看過再按；確認錯了可以按「取消上次整批確認」。
- **請 AI 核對：** 「AI 核對疑點」會把數值不同、版本不同的譯文交給 AI 對照英文核對。正確的記下「AI 已核對」並移出「建議確認」；有錯的改寫成「AI 補譯」，要再按一次「備份並套用譯文」才會寫入。
- **不用逐筆確認：** 報告頁的「備份並套用譯文」會一次套用所有通過檢查的譯文；只有想修改的才需要雙擊。

篩選分成「已翻譯」（依翻譯方式：台灣參考庫、模組繁中、官方譯名、簡中轉繁、AI 補譯等）和「未翻譯」（缺少中文來源、待查程式與設定、無需翻譯），每筆都顯示所在的檔名，方便到資料夾找。程式內部字串（記錄檔訊息、程式碼、識別字）會自動和「待查程式與設定」分開，只留下值得檢查的；模組程式裡確定只拿來丟錯誤或寫記錄檔的句子（例如「Registry does not exist!」）也會分到「無需翻譯」，只要有一處可能顯示給玩家就仍留在待查。

「無法寫入（遊戲中是英文）」是遊戲會顯示、但這個整合包寫不進去的文字，多半寫死在模組程式裡：資源包蓋不過去，CurseForge 又會把改過的模組換回原版，所以遊戲中出現時是英文；程式裡本來就是中文的不列在這裡。「寫入後遊戲讀不到」是寫入後從遊戲讀取的檔案回讀，卻沒有這句的文字（例如資源包沒有啟用）。兩個模組帶了同一個書頁檔時，遊戲只會顯示其中一份，只要那一份是中文，兩句都算已是中文。

「還缺中文」的句數一定等於「缺少中文來源」「無法寫入」「寫入後遊戲讀不到」三個分類，加上已翻好、還沒寫入的句數（這些仍列在已翻譯的分類裡）。報告頁上方的「中文化完成率」「還缺中文」和開始頁是同一組數字。

模組 data 資料夾裡的語系檔（data/模組/lang/）是給伺服器用的：Forge 只讀那裡的英文，不會讀繁中，畫面上的同一句來自 assets 資料夾裡的語系檔，已在那裡翻譯，所以不列入、不算缺。數字檢查會把英文月份當成數字（December 等於 12 月），翻成「12 月」不會被當成改動了數字。

**換行：** 模組作者、翻譯組或你自己寫的中文，行數比英文少時保留原本的斷行，不再硬切成英文的行數（舊版曾把「魚肉鮮嫩麻辣」切在「麻／辣」之間，下次執行會改回來）；AI 的譯文仍依英文行數排好。

## 已翻譯整合包：直接安裝別人翻好的整合包

不用再從雲端下載檔案、自己複製到 CurseForge 資料夾。

1. 打開「已翻譯整合包」頁，會列出已發布翻譯的整合包。每張卡片都有兩組資訊：
   - **整合包版本與發布日期**：整合包本身的版號，例如「整合包版本 1.1.1a（2026-09-18 發布）」。
   - **翻譯版本與更新日期**：同一個整合包版本的翻譯改進後會重新發布，例如「翻譯第 2 版・2026-09-29 更新」。
2. 按卡片上的按鈕：
   - **安裝整合包與翻譯**：電腦上還沒有這個整合包時出現。按下後 CurseForge 會跳出來下載整合包（請在它的視窗確認），程式會自己等它裝好，接著裝上翻譯、把遊戲語言設成繁體中文。等待途中可以按「停止等待」。
   - **安裝翻譯**：電腦上已經有這個整合包時出現。程式會自己找到整合包（裝在自訂位置也找得到），先備份再安裝。
   - **翻譯者加裝的模組**：翻譯者在整合包之外用 CurseForge 加裝的模組（例如解決輸入法卡住的 IMBlocker）會列在卡片上。安裝時確認一次就會一起加入：程式從 CurseForge 的官方檔案伺服器下載，確認和翻譯者用的是同一個檔案才放進模組資料夾，之後可在「備份與還原」移除。
   - **怎麼調整記憶體**：整合包作者有建議記憶體大小時出現，列出在 CurseForge 調整的步驟。卡片也會顯示建議的大小；你的電腦記憶體分完後剩不多時會提醒。
3. 有新上架的翻譯時，側欄的「已翻譯整合包」後面會出現數字（新上架和有更新的總數，滑鼠移上去可看明細）；新上架的正好是你電腦上的整合包時會跳出 Windows 通知。之後翻譯有更新，卡片會標示「翻譯有更新」，按「更新翻譯」即可。

**整合包版本不同時**
- 每個整合包只有一張卡片。程式會挑出和你安裝的整合包版本相同的那一份翻譯，舊版本的翻譯也會保留；有更新版本的翻譯時，卡片會多一行提示。
- 如果沒有你的版本，可以按「仍要安裝」，只翻譯和當時完全相同的模組，其他的略過、不會覆蓋；略過的部分再按一次「一鍵完整翻譯並套用」補齊即可。

翻譯只含文字，不含任何模組檔。內含 CFPA、ModsTranslationPack 等社群譯文，依 CC BY-NC-SA 4.0 免費分享、不得販售。

**整合包和翻譯各從哪裡來**
- **整合包（模組、設定）：** 由 CurseForge 從官方下載，本程式不提供也不散布模組檔。所以電腦要先裝好 CurseForge。
- **翻譯者加裝的模組：** 翻譯裡只記下是哪一個模組的哪一個檔案和它的校驗碼。你選擇加入時，程式從 CurseForge 的官方檔案伺服器下載，確認和翻譯者用的是同一個檔案才放進模組資料夾；不符就不安裝。加入的模組會列在「備份與還原」，還原就會移除。
- **不會自動加入的模組：** 作者只開放由 CurseForge 安裝的、不是從 CurseForge 裝的、你已經裝了別的版本的，都不會動，完成時會列出來並說明怎麼自己加裝。翻譯者把整合包原有的模組換成別的版本時，你保留整合包的版本。
- **翻譯：** 只有繁體中文文字，放在本專案的 GitHub，約幾 MB。
- **記憶體：** 卡片和安裝完成的訊息會顯示整合包作者建議的記憶體大小（取自整合包的 manifest.json），按「怎麼調整記憶體」看 CurseForge 的設定步驟。程式只讀取 CurseForge 目前的設定，不會修改；請在 CurseForge 自行調整。

**下載的翻譯裡有什麼、沒有什麼**
- **有：** 繁體中文的語系檔、書本內容和任務檔，程式也只允許寫入這幾種；英文檔、配方、設定和腳本一律拒絕。模組的翻譯會在你的電腦上組成同樣的翻譯資源包；每個翻譯檔都記著它對應的模組版本，你的模組和翻譯者的完全相同才會放進去。
- **沒有：** 模組檔、設定檔、記憶體和啟動器設定、存檔。安裝翻譯只會在遊戲選項（`options.txt`）裡啟用翻譯資源包，有勾選時也把語言設為繁體中文。翻譯者加裝的模組只有名稱和校驗碼，檔案本身不在裡面。
- **翻譯者另外加裝的模組：** 你沒有裝的話，只會略過那個模組的翻譯，不會幫你安裝模組。

## AI 補翻（選用）

不登入也能翻譯；AI 只做兩件事：補參考庫找不到的部分，以及核對有具體疑點的譯文（數值和原文不同、來自其他版本）。

**讓翻譯越用越準**
- **你確認過的最優先：** 在報告裡確認或修正的譯文會記住，之後翻譯任何整合包，同一個模組的同一句直接使用。
- **AI 翻過的會記住：** 沿用時仍標示「AI 補譯」、順位最後，不會蓋過參考庫或你確認的內容。
- **不會自己學：** 程式不會從沒確認過的譯文學習；沒確認的每次都重新依來源順序挑選，所以多確認才會越來越準。

- 在「AI 帳號與模型」按「安裝官方元件」→「連接 ChatGPT」，在官方網頁登入。
- **會消耗你 ChatGPT 方案的 Codex 額度**（與其他 Codex 工作共用），不使用 API key、不另外收費、不會自動加購。額度不足時會停止並保留已完成的部分。
- 只傳送缺漏的原文、語系鍵與模組內路徑；核對疑點時另外傳送那一筆目前的譯文和疑點說明。不傳整個模組包或存檔。
- AI 譯文會標記為「AI 補譯」，建議抽查。
- **選模型：** 「AI 帳號與模型」頁列出帳號可用的模型，並附上官方說明（已知的說明會顯示繁體中文，滑鼠移上去可看官方原文）、推理強度，以及是否有專屬額度。
- **建議模型：** 程式會標示「建議」的模型，沒有自己選過時預設就用它。建議的依據是官方說明：遊戲文字多是短句，所以選官方描述為快速、省額度、而且額度還能用的模型；沒有這類模型時建議官方預設。你自己選過的模型會被記住，不會被建議蓋掉。官方沒有提供翻譯品質或確切耗量數字，所以這不是品質排名。
- **額度判斷：** 只看 Codex 額度和你選的模型的專屬額度；其他模型的額度用完不會影響你。
- **省額度：** AI 只補參考來源找不到的文字（以 Tensura 為例約 2.4%）。一次送出最多 60 句；補翻時會依實際用量推算剩下還需要多少額度。同一個檔案裡相同的原文只送一次，其他幾筆用同一句譯文，用詞一致也不重複花額度；不同模組的相同英文仍分開送。
- **速度：** AI 補翻與核對會同時送出 2 批，等待時間大約減半，總共消耗的額度不變。額度剩 20% 以下時改回一次一批；官方服務不接受同時送出時，也會自動改回一次一批，不會漏掉或重複送出。
- **額度不夠時：** 在剩 5% 時暫停（每次送出前檢查，同時送 2 批時最多多跑兩批），已完成的 AI 譯文和其他所有譯文照常套用；額度恢復後再按一次「一鍵完整翻譯並套用」，只會補剩下的。

## 整合包更新後

CurseForge 更新整合包時，模組的新版本可能加了新的文字，翻譯資源包裡也可能留著舊版本的譯文。程式開啟時會比對整合包版本；發現翻譯過的整合包已更新，「開始翻譯」頁頂端會提醒，可以直接按「重新翻譯並套用」或「查看已翻譯整合包」。

## 備份與還原

每次套用前，會把要修改的原檔備份到 EXE 旁的 `MCTranslatorData\output\<模組包>\原始備份\`。「備份與還原」頁可以一鍵還原某一批；如果檔案之後被你改過，會先停下來說明，不會覆蓋。

- **套用到一半當機或斷電：** 下次開啟程式會提醒。到「備份與還原」選標示「中斷」的那一批按還原：還是原樣的檔案不動，已經寫入的檔案還原。
- **還原順序：** 同一個檔案（例如翻譯資源包）被兩批翻譯改過時，要先還原較新的那一批；程式會告訴你是哪一批。
- **佔用空間：** 程式會自動清掉自己的暫存檔、舊的參考庫下載、舊的更新下載檔，舊版程式只留最近一個。備份和報告不會自動刪除。

## 更新

開啟程式時會檢查新版，有新版會在右上角提示，**由你決定何時下載安裝**。更新會先驗證檔案，失敗時保留舊版；翻譯紀錄、備份與設定都會保留。GitHub 查詢次數用完時，會改從公開的發布頁確認版本，驗證方式不變。

> 從 v0.4.0 或更舊版本升級時，畫面可能停在「準備重新啟動」。請手動關閉程式，更新會在 2 分鐘內完成並自動開啟新版。v0.4.1 起已修正。每一版的更新內容會直接顯示在「程式更新」頁。

## 目前限制

- 圖片裡的文字、程式寫死的文字、部分動態組句不一定能翻；這些會列在報告的「待查程式與設定」。
- 在 CurseForge 的整合包裡，寫在模組程式裡的文字（不在語系檔裡的）無法保留翻譯，因為 CurseForge 啟動時會把改過的模組換回原版；報告會列出這些文字。例外是能確認語系鍵的設定說明，會放進翻譯資源包，只在遊戲內設定畫面顯示中文。
- 內嵌函式庫資料夾（`data/`）裡的書本頁資源包蓋不過去，在 CurseForge 整合包裡不會寫入。
- 遊戲裡如果自己關掉「MCTranslator-zh_tw」資源包，模組的翻譯就不會顯示；再按一次「一鍵完整翻譯並套用」會重新啟用。
- 自動檢查只確認格式、參數與數值沒被改壞，不保證每句語意都正確。
- 移動 EXE 時請連同 `MCTranslatorData` 資料夾一起移動；這個資料夾含有登入資料，不要分享給別人。
- 數值檢查只比對數字有沒有少或不同，判斷不了語意；列在「建議確認」的仍需要你看過。
- AI 核對不是人工確認：AI 判斷「無誤」的譯文會移出「建議確認」，但 AI 也可能看錯，重要的內容仍建議自己抽查。
- 由模組推測 Minecraft 版本可能不準，推測時報告會註明；建議從啟動器清單選擇整合包。
