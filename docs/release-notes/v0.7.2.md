這一版修正「翻譯都做完了，最後卻寫不進整合包」的問題。

發生了什麼事

- 開著 CurseForge 這類啟動器時，啟動器會盯著整合包的 mods 資料夾，一有新檔案就馬上打開來看。
- 程式寫入模組檔的那一瞬間剛好被它打開，Windows 就拒絕寫入。舊版遇到這種情況會直接停止，並把整批還原，所以結果顯示「已套用 0 筆」。哪一個檔案被擋到並不固定，所以重試也可能在別的檔案再失敗。
- 遊戲檔案沒有被改壞，翻好的譯文也都有保存，只是沒有寫進去。

這一版怎麼處理

- 檔案被其他程式暫時佔用時，程式會稍等再自動重試，不再整批失敗。等待時進度畫面會說明正在等哪一個檔案。
- 如果等了大約半分鐘還是被佔用，才會停止並還原這一批。這時訊息會寫出是哪一個模組檔被佔用，不再顯示看不懂的暫存檔名。
- 從備份還原時也一樣會等待重試。
- 舊版失敗時可能在 mods 資料夾留下一個以 .translation- 開頭的暫存檔，它不是模組，遊戲不會讀取。這一版下次套用時會自動清掉，不會動到其他檔案。

更新後請這樣做

- 開啟上一次的報告，按右下方的「重試套用」，不用重新翻譯。
- 啟動器開著也可以，遊戲本身仍然要先關閉。如果重試後還是失敗，請把啟動器完全關閉再試一次。

請注意

- 這項修正已用模擬的檔案佔用、實際被打開的檔案，以及真實整合包 249 個模組檔的副本測試過。因為不能拿你的遊戲資料夾當測試場，尚未在開著 CurseForge 的真實整合包資料夾裡實測，重試後如果還是失敗請回報。

更新只替換程式本身，翻譯資料、備份與設定都會保留。
